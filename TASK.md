# Тестовое задание: модуль «Аптека»

## Цель

Реализуйте интерфейс каталога лекарственных препаратов на базе этого репозитория.
Пользователь должен видеть список препаратов, добавлять новые записи,
редактировать существующие и удалять записи с указанием причины.

Используйте Vue 3, Vue Router и Element Plus, уже подключённые в проекте.

Дизайн страниц и форм произвольный, но в рамках положительного UX (просто адекватный по канонам классических web страниц), стили Element Plus переписывать не требуется.

## Предметная область

Одна запись каталога описывает конкретный препарат конкретного производителя
в определённой форме выпуска, дозировке и упаковке. Например, таблетки
парацетамола 500 мг, 20 штук в упаковке.

Разные дозировки, упаковки или производители — отдельные записи.

## Данные препарата

| Поле                   | Тип             | Описание и проверка                                                                                                           |
| ---------------------- | --------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `id`                   | string          | UUID записи; пользователь не редактирует                                                                                      |
| `tradeName`            | string          | Торговое наименование, от 2 до 200 символов                                                                                   |
| `dosageForm`           | string          | Лекарственная форма, код из справочника ниже                                                                                  |
| `dosage`               | string          | Дозировка или концентрация, до 100 символов: `500 мг`, `10 мг/мл, 2 мл`, `875 мг + 125 мг`; если неприменима — `Не применимо` |
| `packageQuantity`      | integer         | Количество единиц в потребительской упаковке, от 1 до 1000                                                                    |
| `packageUnit`          | string          | Единица содержимого упаковки, код из справочника ниже                                                                         |
| `manufacturer`         | string          | Производитель, от 2 до 200 символов                                                                                           |
| `country`              | string          | Двухбуквенный код страны производителя по ISO 3166-1 alpha-2, в верхнем регистре; значение из справочника ниже                |
| `registrationNumber`   | string или null | Номер регистрационного удостоверения, до 100 символов; формат свободный                                                       |
| `prescriptionRequired` | boolean         | Признак рецептурного отпуска; форма должна позволять явно выбрать «Да» или «Нет»                                              |
| `notes`                | string или null | Примечание к карточке, до 1000 символов                                                                                       |
| `createdAt`            | string          | Дата создания в ISO 8601 с часовым поясом                                                                                     |
| `updatedAt`            | string          | Дата последнего изменения в ISO 8601 с часовым поясом                                                                         |

### Локальные справочники

Для задания справочники фиксированы и не требуют отдельных API-запросов.

Страна выбирается из локального словаря: в интерфейсе показывается название,
в поле `country` передаётся двухбуквенный код ISO 3166-1 alpha-2.
Для задания достаточно следующего набора.

| `country` | Название  |
| --------- | --------- |
| `RU`      | Россия    |
| `BY`      | Беларусь  |
| `IN`      | Индия     |
| `DE`      | Германия  |
| `FR`      | Франция   |
| `CH`      | Швейцария |

| `dosageForm` | Название  |
| ------------ | --------- |
| `tablet`     | Таблетки  |
| `capsule`    | Капсулы   |
| `solution`   | Раствор   |
| `suspension` | Суспензия |
| `powder`     | Порошок   |
| `ointment`   | Мазь      |
| `cream`      | Крем      |
| `drops`      | Капли     |

| `packageUnit` | Название |
| ------------- | -------- |
| `tablet`      | Таблетка |
| `capsule`     | Капсула  |
| `ampoule`     | Ампула   |
| `vial`        | Флакон   |
| `sachet`      | Пакетик  |

`packageQuantity` — число таких единиц в упаковке.
Например, для флакона суспензии 100 мл указываются `packageQuantity: 1`,
`packageUnit: "vial"`, а объём и концентрация — в `dosage`.
Проверять фармацевтическую совместимость формы и единицы упаковки не требуется.

## Поведение интерфейса

### Список - клиентская таблица (один запрос на все данные)

- При открытии приложения одним запросом загрузите все препараты.
- Поиск, фильтрация и пагинация выполняются на клиенте.
- Колонки - Торговое наименование, Форма, Дозировка, Упаковка,
  Производитель, Страна и Признак рецептурного отпуска.
- Добавьте поиск по торговому наименованию и фильтр рецептурного отпуска:
  «Все», «Рецептурные», «Безрецептурные».
- Реализуйте постраничный просмотр с выбором размера страницы: 10, 20 или 50.
  При изменении поиска, фильтра или размера страницы переходите на первую страницу.
- Предусмотрите состояния загрузки, ошибки с повторным запросом,
  пустого каталога и отсутствия результатов поиска.
- Для каждой записи должны быть доступны действия «Редактировать» и «Удалить».

### Добавление и редактирование

- Форму можно открыть в диалоге или на отдельной странице.
- При редактировании заполните форму текущими данными выбранного препарата.
- Покажите обязательность полей и ошибки валидации рядом с полями.
  Если при редактировании ничего не изменилось, запрос сохранения не отправляется.
- Отмена закрывает форму без изменения данных.
- Во время сохранения покажите состояние выполнения и исключите повторную отправку.
- После успеха закройте форму и обновите таблицу новым общим запросом и покажите уведомление.
- При ошибке сохранения оставьте форму открытой и сохраните введённые значения.

### Удаление

Перед удалением покажите название препарата, дозировку и производителя,
запросите подтверждение и причину.

| `reason`          | Причина                                           |
| ----------------- | ------------------------------------------------- |
| `duplicate`       | Дублирующая запись                                |
| `incorrect_entry` | Карточка создана ошибочно                         |
| `discontinued`    | Препарат больше не используется в каталоге аптеки |
| `other`           | Другая причина                                    |

Причина обязательна. Комментарий необязателен, кроме причины `other`:
в этом случае требуется от 10 до 500 символов после обрезки пробелов.
Для остальных причин максимальная длина комментария — 500 символов.
Подтверждение без причины или с невалидным комментарием недоступно.

Во время запроса исключите повторное подтверждение. При ошибке оставьте диалог
открытым и покажите сообщение.

## API-контракты

Запросы и ответы с телом используют JSON
и `Content-Type: application/json`. Авторизация не требуется.
Даты в этом учебном API передаются в ISO 8601 UTC, например `2026-10-23T10:00:00.000Z`.

Валидацию всех условий запросов проводим на фронтенде, требования описаны в таблице Данные препарата - принадлежность к словарю, длина.

### Пример полной записи - IMedicine

```json
{
  "id": "6e080260-71d7-4d9a-955a-8c649b848553",
  "tradeName": "Парацетамол",
  "dosageForm": "tablet",
  "dosage": "500 мг",
  "packageQuantity": 20,
  "packageUnit": "tablet",
  "manufacturer": "Учебный фармпроизводитель",
  "country": "RU",
  "registrationNumber": null,
  "prescriptionRequired": false,
  "notes": null,
  "createdAt": "2026-10-23T10:00:00.000Z",
  "updatedAt": "2026-10-23T10:00:00.000Z"
}
```

### 1. Список — `GET /api/medicines`

Запрос без query-параметров возвращает все препараты одним ответом.

Ответ `200 OK`:

```json
{
  "items": IMedicine[]
}
```

Количество результатов после фильтрации и число страниц вычисляет клиент.

### 2. Добавление — `POST /api/medicines` и Редактирование — `PATCH /api/medicines/{id}`

```json
{
  "tradeName": "Парацетамол", // required
  "dosageForm": "tablet", // required
  "dosage": "500 мг", // required
  "packageQuantity": 20, // required
  "packageUnit": "tablet", // required
  "manufacturer": "Учебный фармпроизводитель", // required
  "country": "RU", // required
  "registrationNumber": null,
  "prescriptionRequired": false, // required
  "notes": null
}
```

### 3. Удаление — `DELETE /api/medicines/{id}`

```json
{
  "reason": "other", // required
  "comment": "Запись перенесена в другой каталог" // required при reason=other, до 500 символов
}
```

### Формат ошибок - используем как референс для обработки в catch при показе уведомлений и т.п.

```json
{
  "error": {
    "code": "INTERNAL_ERROR",
    "message": "Не удалось сохранить препарат. Попробуйте ещё раз."
  }
}
```

Этот формат относится к ошибкам выполнения операции. Ошибки полей показываются
локально средствами формы.
